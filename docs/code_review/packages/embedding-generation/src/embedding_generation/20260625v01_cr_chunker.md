## Correctness Confirmation (no defect found)

The token-budgeted greedy packing, overlap walk-back, and forward-progress guards were traced and are correct:

- **Forward progress / no infinite loop**: Each iteration of `while start < n` (line 139) emits `words[start:end]` with `end > start` guaranteed by the oversize-word guard (lines 146-147), then advances `start = next_start`. `next_start` is floored to `start + 1` (lines 167-168), so `start` strictly increases every iteration and the loop terminates.
- **No dropped or duplicated words / union covers every word in order**: `next_start` is computed by walking back from `end` and is bounded in `[start + 1, end]`. Because the emitted chunk ended at index `end` (exclusive) and the next chunk begins at `next_start <= end`, index `end` (the first not-yet-covered word) is always re-included or is exactly the next start, so no word between consecutive chunks is skipped. The concatenation of chunks in order therefore covers `words[0..n)` with no gap.
- **Oversize single word** (a word whose own token count exceeds `max_tokens`): the greedy inner loop leaves `end == start`; line 146-147 forces `end = start + 1`, emitting that word alone as an oversize chunk. The subsequent overlap loop condition `next_start > start + 1` (line 159) is immediately false, so `next_start = end` and the loop advances by exactly that one word — no stall, no drop.
- **Overlap exceeding a single word's budget**: when the trailing word alone exceeds `overlap_tokens`, the walk-back never executes and `next_start` stays at `end` (no overlap), which is the correct degenerate behavior.
- **Word-boundary preservation**: words are only ever sliced from the pre-split `words` list and rejoined with `" ".join(...)`; no word is ever split mid-token. Confirmed.
- **Input validation**: `max_tokens > 0`, `overlap_tokens >= 0`, and `overlap_tokens < max_tokens` are all checked up front (lines 59-69) with logged `ValueError`s, satisfying exception-handling.md (specific type, context in message, fail-fast).
- **`count_tokens` callable contract**: typed `Callable[[str], int]` and documented as the model's tokenizer (special tokens included); used consistently for both the split decision (line 81) and packing (line 142).

## Edge Case (unreachable from caller — informational)

`_split_words_by_tokens([], ...)` returns `[]` (the `while start < n` loop never runs), which would drop a section. This path is **unreachable from the real caller**: `chunk_long_sections` only calls `_split_words_by_tokens` when `count_tokens(content_text) > max_tokens` (line 81), and whitespace-only / empty text tokenizes to only the model's special tokens (~2), which is `<= max_tokens`, so such input takes the passthrough branch (lines 81-85) instead. No change required; documented here for completeness.
