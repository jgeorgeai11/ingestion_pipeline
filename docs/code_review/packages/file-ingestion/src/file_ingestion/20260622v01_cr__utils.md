## Summary

`code/file_ingestion/_utils.py` is a small, well-documented helper module holding two injection-guard validators (`validate_sql_identifier`, `validate_collection_path`) and a schema-bootstrap function (`ensure_schema`). Overall quality is high: type hints are complete and modern, docstrings are thorough Google-style, logging follows the project pattern, and exception handling uses specific exception types with `try/except/else` and re-raise. The findings below are mostly robustness hardening rather than correctness bugs.

**Findings by severity:** 0 critical, 0 major, 5 minor, 3 suggestion.

Top issue: both compiled regexes are matched with `re.match` and anchored with `$`. In Python `$` matches immediately before a trailing newline, so a value such as `"public\n"` passes both validators (verified empirically). This is a latent weakening of the injection guards; the defenses depend on `$` being a hard end-of-string anchor. Use `re.fullmatch` (or `\Z`) so a trailing newline is rejected.
