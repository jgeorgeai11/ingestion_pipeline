## Scope

Full review of the CURRENT state of `code/file_ingestion/ingest.py` after two substantial changes since v01 (`20260622v01_cr_ingest.md`): (1) the pipeline was made RESILIENT — `step_parse`/`step_clean`/`step_load` now return `(ok_files, failures)` instead of raising on the first failure, and `main()` threads survivors stage to stage (parse->parsed_ok->clean->cleaned_ok->load), aggregates failures, logs a summary, and exits 1 if any failed; (2) document PROVENANCE — `step_clean` unpacks `(sections, binary_hash)` from `parse_docling_json` and `step_load` reads `cleaned.document.binary_hash` / `cleaned.document.n_parsed_sections` from the new `document` envelope and inserts `source_binary_hash`. Collaborators (`cleaned_models.py`, `docling_section_parser.py`, `sql/schema.sql`, `file_parser.py`, `_utils.py`) were read for context but are out of scope. All five v01 findings (1.1 title-required, 1.2 duplicate-file fail-fast, 2.1 `URL.create`, 3.1 folded existence read into the write transaction, 4.1 all-dropped fail) remain resolved in the current code — no regression. The findings below are new, surfaced by the resilience and provenance changes.
