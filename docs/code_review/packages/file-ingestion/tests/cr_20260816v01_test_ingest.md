1. [completed] The suite cannot be run with the project's own pytest configuration - `code/file_ingestion/unit_tests/test_ingest.py`
   - 1.1. [minor] `uv run pytest code/file_ingestion/unit_tests/test_ingest.py` aborts with `INTERNALERROR> AttributeError: module 'code' has no attribute 'InteractiveConsole'` before a single test runs, from any working directory. Cause: `pyproject.toml` sets `addopts = "--import-mode=importlib"`, and importlib mode synthesises the parent packages of the rootdir-relative module path — inserting a dummy `code` module into `sys.modules` that shadows the standard library's `code`, which `_pytest.debugging.pytest_configure` needs via `import pdb`. The repo's source directory is literally named `code/`, so every test module in this project is affected. Confirmed: `-p no:debugging` gives `53 passed in 1.28s`, and `--import-mode=prepend` gives `53 passed in 1.19s`. The consequence for this file is that the unit-tests skill's guideline 7.2 (run `pytest --cov=... --cov-report=term-missing` and address uncovered lines) cannot be satisfied with the documented invocation; coverage for this review had to be measured with `-p no:debugging` (96%, missing `ingest.py` 87-89, 97-113, 851).
        - Current: `pyproject.toml` → `addopts = "--import-mode=importlib"`, with the module under test living under a package path beginning `code.`.
        - Expected: make the configured invocation work again — e.g. drop `--import-mode=importlib` in favour of the `consider_namespace_packages`/`rootdir`-independent arrangement, set `pythonpath`/`rootdir` so the derived module names do not start with `code`, or (least invasive) `import code` at the top of `unit_tests/conftest.py` so the real stdlib module is already in `sys.modules` before pytest inserts its placeholder. The fix lands in `pyproject.toml` or `unit_tests/conftest.py`, not in this test file, but it gates every guideline-7 check for it.
        - Resolution: Already fixed repo-wide before this task was worked, by a new repo-root `conftest.py` that pre-imports the stdlib `pdb` (with a docstring explaining the `code/`-shadows-stdlib mechanism). Its author's finding refines the suggested fix: pre-importing `code` alone is *not* sufficient, because pytest replaces `sys.modules["code"]` regardless (the stdlib `code` is a module, not a package, so it has no `__path__` and `need_reimport` fires) — `pdb` is what must be cached while `code` is still intact, and a root conftest is imported early enough to do it. `--import-mode=importlib` is therefore kept (dropping it would break the `test_utils.py` basename collision between `file_ingestion` and `excel_ingestion`). No change made here; verified with the documented invocation: `uv run pytest code/file_ingestion/unit_tests/test_ingest.py --cov=ingest --cov-report=term-missing` → 63 passed, `ingest.py` at 99% (only the `main()` call under `if __name__ == "__main__"` uncovered), and `uv run pytest code/` → 597 passed.
